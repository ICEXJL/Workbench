# 跨境工作台物流查询设计

## 目标

在现有瀛江科技工作台中新增“跨境工作台”导航分区和“物流查询”页面，所有登录角色均可使用，复用 5 张 `logistics_` 表提供按 SKU/自定义 SKU/产品名查询的只读物流视图。货柜表增加 `container_no` 并纳入主键；业务数据仍由独立 ETL 导入。

## 已确认的业务口径

- 所有角色都可以进入物流查询。
- 所有角色都可以查看和切换全部物流仓库。
- 首次进入默认是全部仓库跨仓视图；用户可选择单一发货仓。
- 后端必须强制执行仓库筛选和 SKU 隔离，前端选择器不能作为安全边界。
- 查询支持单个值、反斜杠分隔的多 SKU，最多 20 个；也支持产品名关键词。
- 页面展示产品档案、库存/采购价、货柜进度、补货记录、未发货采购单、已发货记录和批次-货柜映射。
- 货柜标题显示真实柜号；J 列一个单元格含多个柜号时分别生成货柜记录。已送仓货柜排在在途记录前，并按实际送仓日期倒序。
- 货柜卡片显示本柜海运备货数：按同一 SKU、发货仓和装柜/给货日期匹配 `EMITTED` 发货记录的 `qty2`；无匹配记录时显示空值。补货表仍按近两个月 `sea_qty` 展示，没有近期补货记录时隐藏补货表。
- 预计送仓/实际送仓信息小模块不显示，实际送仓字段仍参与货柜排序。

## 方案

### 后端

新增 `backend/services/logistics_service.py` 和 `backend/routers/logistics.py`。

- `GET /api/v1/logistics/warehouses` 返回可用发货仓、SKU 数量和当前默认仓。仓库列表按物流表的 `warehouse` 字段汇总；默认不锁定仓库。
- `GET /api/v1/logistics/search?q=<query>&warehouse=<warehouse>` 返回最多 20 个 SKU 的分组结果。
- 查询解析：反斜杠/换行/逗号分隔的值按多个查询词处理；一到二十个明确 SKU 优先按 `sku` 或 `custom_sku` 精确匹配；单个非精确值按 `product_name` 关键词匹配。
- 先查询 `logistics_sku` 得到 SKU 与仓库，再分别查询 `logistics_container`、`logistics_replenish`、`logistics_shipment`、`logistics_shipment_container_map`。禁止将这些表串联 JOIN，避免一对多笛卡尔积。
- 每条查询都使用参数绑定。仓库条件只接受仓库列表接口返回的值；未知仓库返回 400。物流表缺失或 SQL 错误返回 503，不泄露数据库异常。
- 返回结构按 SKU 分组，保留每个仓库的产品档案与物流记录，避免跨仓视图丢失同 SKU 的仓库差异。货柜状态返回原始状态、进度字段和轨迹文本，前端负责展示进度。

### 前端

修改 `MainLayout.vue`、`router/index.js`、`services/api.js`，新增 `views/logistics/LogisticsSearch.vue`。

- 导航第一分区为“跨境工作台”，只包含物流查询；原“经营分析”和“组织管理”顺序及角色过滤保持不变。
- 物流页面使用当前工作台的科技蓝、白底、细边框风格；顶部是搜索输入、仓库选择和查询按钮，下方按 SKU 展示结果区块。
- 结果区块使用紧凑信息卡展示可用库存、采购中、采购价、近两月海运备货数和 SKU 所在仓；货柜按单列卡片展示真实柜号，卡片各自包含五阶段进度、目的仓、承运信息和本柜跟单轨迹折叠区。
- 补货记录保持独立表格，仅展示最近两个月并按登记日期倒序；未发货与已发货采购记录合并到一个海运记录表，`qty2` 按 `record_type` 分别标注为入库数量或发货总数，`is_done = NULL` 显示未知。
- 查询中、空结果、仓库加载失败、后端未启动和物流表错误均有明确反馈；保留上一次查询结果，避免请求失败时页面跳空。
- 查询输入回车可执行，结果数量和当前仓库口径始终可见；多 SKU 返回各 SKU 的独立标题。

## 非目标

- 页面 API 不提供物流业务数据导入、编辑或删除。
- 柜号字段通过人工执行的一次性升级 SQL 增加；本任务不直接连接或修改数据库。
- ETL 从海运工作簿 J 列提取一个或多个箱号/柜号。导入器会清空并重载目标仓物流记录，不由本项目自动触发。
- 不把物流查询接入角色层级过滤；本次业务确认的是所有角色查看全部仓库。
- 复用工作台的页面外壳、导航与接口，不另建旧 HTML 的独立站点或 API；物流内容区参照旧页面的信息顺序和货柜轨迹交互。

## 验证标准

- 后端测试覆盖：查询解析上限、仓库参数绑定/拒绝未知仓库、产品档案缺失时按货柜 SKU 查询、忽略缺仓库明细、查询结果按仓库分组和货柜排序、五张表不发生串联 JOIN、空结果和缺表错误。
- 前端单测覆盖：五阶段进度、签收状态、真实柜号标签、海运备货汇总、海运记录类型与 `qty2` 口径、完成状态三值显示、最近两个月补货过滤及倒序。
- 前端构建必须通过。
- Python 语法检查必须通过。
- 启动服务后，用一个已登录角色验证 `/logistics/warehouses` 和 `/logistics/search`；至少检查全部仓库、单仓和多 SKU 三种请求。
- 数据库升级 SQL 不在开发验证中执行；导入器仅运行纯内存单测，不连接数据库或重载数据。
