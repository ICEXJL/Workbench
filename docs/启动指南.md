## 0. 首次配置（只做一次）

### 0.1 准备 Python 环境

本机已装好 Python 3.13。建议用虚拟环境，避免污染系统环境：

```bash
cd C:/Users/Administrator/Desktop/WorkSpace/project005_订单管理系统/backend

python -m venv .venv

# Windows Git Bash 下激活：
source .venv/Scripts/activate

pip install -r requirements.txt
```

> **坑**：`python-jose` 在清华镜像里没有。如果 `pip install` 报
> `from versions: none`，改用官方源：
> ```bash
> pip install python-jose[cryptography] -i https://pypi.org/simple
> ```

### 0.2 配置 `.env`

```bash
cp .env.example .env      # Windows 也可以直接手动复制改名
```

然后编辑 `backend/.env`，至少填这几项：

```ini
DB_HOST=47.114.36.52
DB_PORT=3306
DB_USER=progress
DB_PASS=<真实密码>
DB_NAME=东南亚运营数据
SECRET_KEY=<至少 32 位随机串>
```

生成 `SECRET_KEY`：

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

> ⚠️ `SECRET_KEY` 不填或填得太短，**后端会直接拒绝启动**（这是故意的安全校验）。
> `.env` 已被 Git 忽略，不会误提交。

### 0.3 安装前端依赖

```bash
cd ../frontend
npm ci
```

## 1. 记住这两条"前提规则"

不管怎么启动，下面两条必须遵守，否则会遇到莫名其妙的问题。

### 规则一：先清代理变量

你本机设了系统代理 `127.0.0.1:56975`。**它会劫持 localhost 请求导致 502**，
表现是「前端打不开」或「接口全部超时」，但代码和服务其实都正常。

所以**每次启动前都要执行**：

```bash
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY
```

### 规则二：开两个终端窗口

前后端必须**同时运行**，且各自占一个窗口。关掉窗口服务就停了。

> 之后窗口 1 就能简写成 `py main.py`。

## 3. 怎么确认启动成功

| 检查项 | 怎么看 | 正常结果 |
| --- | --- | --- |
| 后端活着 | 浏览器开 http://127.0.0.1:8000/health | `{"status":"ok"}` |
| 前端活着 | 浏览器开 http://localhost:5173/ | 登录页 |
| 前端能连后端 | 在登录页输账号点登录 | 正常进首页 / 报账号密码错 |
| 端口占用 | `netstat -ano \| grep -E ":(8000\|5173)\s"` | 两个 0.0.0.0 监听 |

> **重要**：登录报「账号或密码错误」**不代表服务有问题**，可能只是密码不对。
> 服务本身是否正常，要看 `/health` 那个接口。

## 4. 停止服务

**最简单**：关掉那两个终端窗口（会问是否终止，选 Y）。

如果窗口找不着了，或者想确认干净：

```bash
# 查端口占用的进程号
netstat -ano | grep -E ":(8000|5173)\s+.*LISTENING"
```

会看到类似这样的输出，**最后一列就是 PID**：

```
  TCP    0.0.0.0:5173    0.0.0.0:0    LISTENING    27540
  TCP    0.0.0.0:8000    0.0.0.0:0    LISTENING    44748
```

结束指定进程 —— **注意斜杠写法在两种终端里不一样**：

| 你用的终端 | 命令 |
| --- | --- |
| **Git Bash** | `taskkill //PID 44748 //F` |
| **CMD / PowerShell** | `taskkill /PID 44748 /F` |

> 原因：Git Bash 会把单个 `/` 当成路径起始符，所以要写成 `//`。
> 这是个很常见的坑，报「参数无效」就是这里写错了。

## 5. 常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 页面能开但接口全 502/超时 | 代理劫持 | 启动前 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY` |
| 后端起不来，提示 `SECRET_KEY 未配置` | `.env` 没配或漏了这项 | 检查 `backend/.env` |
| 后端提示 `SECRET_KEY 过弱` | 用了示例值或长度 < 32 | 用 `python -c "import secrets; print(secrets.token_urlsafe(48))"` 重新生成 |
| `Address already in use` / 端口被占 | 上次没关干净 | 见第 4 节，`taskkill` 掉进程 |
| `ModuleNotFoundError: No module named 'jose'` | 缺 `python-jose` | 用官方源装：`pip install python-jose[cryptography] -i https://pypi.org/simple` |
| 装依赖报 `from versions: none` | 清华镜像缺包 | 同上，换官方源 |
| `npm run build` 报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` | 批量删除保护（`dist/assets` 文件超阈值） | 绕法：`npx vite build --outDir dist-verify --emptyOutDir false` |
| 改了后端代码但页面行为没变 | 后端没重启 | 停掉后端重新 `python main.py` |
| 改了前端代码但页面没变 | Vite 没热更新 | 硬刷新：`Ctrl + Shift + R` |

## 6. 前端构建（上线时才需要，日常开发不用）

```bash
cd frontend
npm run build
```

产物在 `frontend/dist/`。部署时用 Nginx 托管，并**必须配 SPA 回退**，
否则直接访问 `/statsdaily` 这类子路由会 404：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```
