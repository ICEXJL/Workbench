## 七、易踩坑点（实测确认）

1. **`denglu` 无主键无唯一索引**：`username` 唯一性靠应用层保证，批量写入需自行判重。
2. **`dp_ry` 无主键**：`dpbh` 可能重复；`yy`/`zm`/`zg` 是**姓名文本**，改名即断关联；`zm` 注释为「组名」实际存组长姓名。
3. **`dny_data`/`fbs_data` 数值列全是 varchar**：聚合需 `CAST(... AS DECIMAL)`。
4. **`org_hierarchy.dept`/`effective_from`/`effective_to` 全 NULL**：组织链只有 id 三元组，部门归属以 `dp_ry.bm`/`operator.department` 为准。
5. **`operator.status`/`created_at`/`updated_at`、`org_hierarchy.updated_at`、`target_monthly.status`/`updated_at` 无默认值**：INSERT 必须显式赋值。
6. **`logistics_shipment.qty2` 一列两义**：看值先看 `record_type`。
7. **物流表 `warehouse` 有默认值 `PH-SAN-RAFAEL-3`**（三仓），漏传会静默写进三仓。
8. **`snap_date` 全 NULL、4 个 cnt 列全 0**：物流关联统计功能未回填，页面若展示这些数字会是空的。
9. `user` / `hermes_*` 为预留或演示表，0 行，勿在业务 SQL 中引用。
