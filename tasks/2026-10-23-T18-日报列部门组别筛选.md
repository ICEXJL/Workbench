## 1. 需求

1. 日报列表页在日期筛选旁新增「部门」「组别」两个**联动**筛选：
   选部门后组别只显示该部门下的选项，运营筛选随部门/组别收窄。
2. `/report/people` 返回每个人的部门和组别；日报列表查询把
   `department`、`group` 传给后端，**由后端在权限范围内过滤**，
   不只过滤前端当前页。
3. 「上涨」只把这两个字显示为绿色，「下滑」只把这两个字显示为红色，
   数量与店铺名保持中性色；抽屉详情同步。
4. 顺序：先补后端筛选测试 → 改前端 → 跑后端测试、前端测试、构建。

## 2. 后端改动

### 2.1 新增 `_split_multi()`

`dp_ry` 的部门/组别经 `GROUP_CONCAT` 聚合后可能是多值（「武汉一部、深圳一部」），
必须拆开逐项比对，等值匹配会漏人。兼容中文顿号与逗号，自动去空白。

### 2.2 新增 `filtered_operator_ids()`

```python
filtered_operator_ids(user, department=None, group=None) -> list[int]
```

实现策略：**先取 `visible_operator_ids` 作为硬边界，再用 `visible_people`
的部门/组别二次筛选**。

为什么不用 SQL 层过滤：

- `department` 由 `COALESCE(o.department, p.department, MAX(h.dept))` 聚合而来，
  无法在 `WHERE` 里用聚合；只能 `HAVING` + `FIND_IN_SET`，在
  `ONLY_FULL_GROUP_BY` 下容易出问题。
- `list_reports` 原 SQL **不含** `group_name`，SQL 层过滤需同时改子查询、
  SELECT 和 HAVING 三处。
- 服务层过滤复用 `visible_people`，与 `/report/people` 口径**天然一致**，
  避免两处各算一套导致下拉选项与实际结果不符。
- 代价是多一次查询；221 人规模下开销可忽略。

**安全性质**：结果始终是 `visible_operator_ids` 的子集，筛选只能收窄，
不会扩大可见范围。函数内还有一次 `if person_id not in ids: continue` 兜底。

### 2.3 `list_reports` / `compliance_overview` 改用该函数

两者共用同一范围函数，保证「指标卡片数字」与「日报表格行」口径一致
（实测：不筛部门 221 人/757 条，筛武汉一部 43 人/129 条，卡片统计同为 43）。

### 2.4 路由新增 query 参数

- `GET /report/daily`：新增 `department`、`group`
- `GET /report/compliance`：新增 `department`、`group`

已通过 `/openapi.json` 确认参数注册成功。

## 3. 前端改动

### 3.1 新增纯函数模块 `src/utils/reportFilters.js`

`splitMulti` / `getDepartmentOptions` / `getGroupOptions` / `filterReportPeople`。

放在 utils 而非组件内，是为了**可单元测试**——`frontend/tests/dailyReportList.test.js`
在本次改动前就已写好并一直失败（引用了不存在的模块），本次补上实现后转为通过。

### 3.2 `DailyReportList.vue`

- 筛选区新增部门、组别两个 `a-select`，均支持清空
- 联动：换部门 → 清空组别与运营；换组别 → 清空运营
- 未提交人员补行（`scopedPeople`）也改用收窄后的 `operatorOptions`，
  避免出现「筛选了部门但补行里冒出其他部门的人」
- 请求参数追加 `department`、`group`

### 3.3 涨跌配色

改前：整行着色（`.variation-table-line.fall{color:#c24c48}`），
数量与店铺名被迫继承红/绿色。

改后只给方向词着色：

```css
.variation-table-line.rise .variation-direction{color:#237b59}
.variation-table-line.fall .variation-direction{color:#c24c48}
.variation-table-line strong{color:#24344d}          /* 数量 */
.variation-table-line .variation-names{color:#71809a} /* 店铺名 */
```

保留淡色背景（`#eef8f2` / `#fdf1f0`）用于区分涨跌，但不影响文字。

抽屉详情原本就只给 `>span` 着色、`strong`/`p` 已为中性色，
本次未改动，与表格达成视觉一致。

### 4.2 调整一处既有测试

`tests/test_rbac_permissions.py::test_list_reports_applies_department_and_group_filters`
原本断言 SQL 文本含 `:department` / `:group_name`，并把参数命名为 `group_name`。

该断言与实现方式过度耦合，改为断言「筛选参数被正确交给 `filtered_operator_ids`」，
保留其真实意图（筛选在服务端生效）。

### 4.3 前端测试命令修正

`node --test tests/`（目录写法）在 Node 22.22 下会把目录本身当测试加载而失败；
正确写法是 `node --test tests/*.test.js`。已在 `package.json` 增加：

```json
"test": "node --test tests/*.test.js"
```
