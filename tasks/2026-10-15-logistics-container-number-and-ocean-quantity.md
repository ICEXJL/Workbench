# 物流真实柜号与海运备货数量

## 状态

代码、文档和自动化测试已完成。数据库升级 SQL 与仓库数据导入尚待管理员手动执行；本任务没有连接或修改数据库，也没有运行会删除并重载仓库数据的导入器。

## 已确认需求

- 使用海运工作簿 J 列货代文本中的真实箱号/柜号替代页面序号。
- J 列单元格可能包含多个柜号，每个柜号都要单独生成货柜记录。
- 最新已送仓货柜排在前面；在途货柜排在已送仓货柜之后。
- 移除货柜卡片中的预计送仓/实际送仓信息小模块。
- 海运备货数量按柜展示：同一 SKU、发货仓下，使用货柜 `load_time` 匹配 `EMITTED` 发货记录的 `handover`，读取该记录的 `qty2`；没有匹配发货记录的货柜不显示数量。补货表仍按 SKU+发货仓展示近两个月 `sea_qty`。
- 没有近两个月补货数据时隐藏补货记录区。
- 增加 `logistics_container.container_no` 字段，并把它纳入复合主键。

## 实现

- 后端按已送仓状态、实际送仓日期、装柜日期进行排序；支持完整日期和月日格式。
- 前端卡片使用真实柜号标签，并移除预计/实际送仓小模块。
- 后端按 SKU+仓库和装柜/给货日期把 `EMITTED.qty2` 挂到对应货柜；前端只显示本柜数量，补货数据为空时隐藏补货表。
- `C:\Users\Administrator\Desktop\物流数据仓库\etl\load_wh_generic.py` 从 J 列文本提取柜号，并为同格多柜生成多行；内存去重键包含柜号。
- 一次性升级脚本：`docs/2026-10-15-logistics-container-no.sql`。
- API 行为说明：`docs/API_LOGISTICS.md`。

## 上线注意

1. 先备份数据库并由数据库管理员执行一次性升级 SQL。脚本不是幂等的，不会由 FastAPI 自动执行。
2. 部署后端和前端代码。
3. 由数据管理员确认目标仓和备份后，运行导入器。导入器会删除并重载目标仓物流记录。
4. 查询一个已签收柜号、多柜同格场景及一个近两个月有海运备货的 SKU，核对页面卡片和数量。

主键变更可能导致 InnoDB 重建表并持有元数据锁，建议在低峰期执行。回滚前先检查是否存在仅由 `container_no` 区分的记录；若存在，旧主键无法容纳全部数据，不能直接回滚。
