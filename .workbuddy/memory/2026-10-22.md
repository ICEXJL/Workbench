## 人员销售排序问题的结论（用户反馈"不是按销售额排序"）

**结论：排序是对的**，代码 `sales_service.py:211` 是 `ORDER BY total_sales DESC, yy`。
前端 `PersonnelSales.vue` 零排序代码，`rows.value = data.items` 直接透传。

用户误判的原因：表格横向有 7 个日列 + 订单数 + 销售额共 9 列，
**看串了列**——截图里邢菊某天 8811.02 低于陈丽莎 10120.25，
但 7 天累计邢菊 61244.67 高于陈丽莎 59014.36，所以邢菊排前面是正确的。

另一个易误解点：**订单数与销售额走势不一致**。实测 10-15 数据，
邢菊订单 51500 高于熊小娅 40552，但销售额 57917 < 58213，排后面。
如果用户盯订单数列看，会以为排序错了。

10-19 实际数据（已核实）：邢菊 61244.67 排第 5，陈丽莎 59014.36 排第 6。

- A：固定改 `ORDER BY xs7 DESC`（xs7 = 基准日当天）

**用户未选。下次问。**

必须注意的坑（已在对话中说明）：
1. 次级排序键 `yy` 不能省，否则并列时翻页会重复/丢行
2. 当天无数据是 0 不是 NULL（`SUM(CASE WHEN...THEN xse ELSE 0 END)`）
3. 前端 `cacheKey` 要加 `sort_by`，否则切换排序会命中旧缓存
4. 排序字段必须白名单映射，不能拿前端字符串直接拼 SQL
