## 货柜排序改为「未送仓优先」

**用户反馈**：货柜物流状态板块，很多已送仓的显示在前面，希望在途/未到送仓的优先。
并说"之前设置过时间优先，效果不好"。

**根因**：`_container_sort_key` 返回 `int(delivered)` + 调用处 `reverse=True`，
已送仓（delivered=1）排最前。而全库 **91% 的货柜已签收**：

| stage | 状态 | 数量 |
| --- | --- | --- |
| 2 开船 | 在途 | 5,823 |
| 3 到港 | 在途 | 6,799 |
| 5 送仓 | 在途 | 792 |
| 5 送仓 | 已签收 | **121,558** |

所以 12,622 个在途柜被压到最底部。

**另一个发现**：`logistics_container.sort_key` 列 **133,190 行全是 0**，
注释写着"在途优先+时间倒序"但 ETL 根本没填。旧测试还在断言它，
属于**测试锁定了失效字段**，已一并改掉。

### 新排序规则

```
1. 未送仓 整组 排在 已送仓 之前
2. 未送仓内部：stage_seq 降序（5→3→2，越接近送仓越前）
3. 同阶段：装柜时间倒序
4. 已送仓内部：actual_in 倒序（最近送仓在前）
```

**「已送仓」判定**（`_is_delivered`）：`actual_in` 有值 或 status 含
已签收/已送仓/已入仓。**不看 stage_seq**——存在 stage=5 但在途的记录
（如 TIIU5689474），它们靠 actual_in 才判对。

### 改动

- `backend/services/logistics_service.py`：抽出 `_is_delivered()`；
  重写 `_container_sort_key()` 用负号表达倒序、返回 4 元组；
  调用处 `reverse=True` **去掉**（否则规则被翻转）
- `tests/test_logistics_service.py`：新增 3 项（`_is_delivered` 边界、
  未送仓优先、排序不丢行）；**改写 2 项旧测试**——
  原 `..._places_latest_signed_containers_before_transit_rows` 锁的是旧需求，
  改为 `..._places_transit_containers_before_signed_ones`；
  原 `..._by_latest_sort_key_first` 依赖全 0 的 sort_key，改为验证装柜时间倒序
- `docs/API_LOGISTICS.md`：更新排序描述与调整原因

### 验证

- 后端 **109 passed**（106 → +3）
- 实测 SKU=3272633：36 柜，未送达 5 个全在前（stage 3,3,3,3,3 降序），已送达 31 个在后
- 实测 SKU=2605100：37 柜，未送达 2 个在前（stage 3,2），已送达 35 个在后
- 服务已重启（PID 142620）

### 注意

改排序时**必须同时检查调用处的 reverse 参数**。key 里已经用负号表达倒序，
再加 reverse=True 会整体翻转，规则失效。已加注释说明。

## 日报全量表格：固定表头

用户要求往下滚动时表头保留。

原因：`a-table` 只设了 `:scroll="{x:1900}"`，只有横向滚动；
**Ant Design 必须有 `scroll.y` 才会把表头与表体分离**，表头才能固定。

改为 computed `allTableScroll`：

```js
const allTableScroll = computed(() => ({
  x: 1900,
  ...(displayRows.value.length > 12 ? { y: 'calc(100vh - 320px)' } : {}),
}))
```

- 行数 ≤12 时不给 `y`，避免少量数据被撑成固定高度、下方留白
- 洞察区表格（problemRows）未改，仍是 `{x:1900}`

前端 21 passed，构建 17.73s。

**注意交互差异**：antd 的做法是「表格内部滚动 + 表头固定」，
不是「页面滚动 + 表头吸顶」。如果用户想要后者，需改用 CSS
`position: sticky` 打在 `.ant-table-thead` 上，并处理 z-index 与横向固定列的冲突。
