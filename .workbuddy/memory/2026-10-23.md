### 后端实现选择（重要，下次别推翻）

新增 `filtered_operator_ids(user, department, group)`，走**服务层过滤**而非 SQL：
先取 `visible_operator_ids` 作硬边界，再用 `visible_people` 的部门/组别二次筛选。

不选 SQL 层的原因：
- `department` 是 `COALESCE(o.department, p.department, MAX(h.dept))` 聚合值，
  WHERE 里用不了聚合，只能 HAVING + FIND_IN_SET，ONLY_FULL_GROUP_BY 下易炸
- `list_reports` 原 SQL 压根没有 group_name，要改子查询+SELECT+HAVING 三处
- 服务层复用 `visible_people`，与 `/report/people` 口径天然一致
- 代价是多一次查询，221 人规模无感

**安全性质**：结果始终 ⊆ visible_operator_ids，只能收窄不能扩大。

`list_reports` 和 `compliance_overview` 共用这个函数——保证卡片数字和表格行一致。
