# 瀛江科技工作台

面向东南亚跨境电商运营团队的内部数据工作台。当前提供登录、销售查询、运营日报和月度目标配置；仍处于开发验收阶段，**不应作为已完成的生产系统发布**。

## 技术结构

```text
frontend/   Vue 3 + Vite + Pinia + Vue Router + Ant Design Vue + ECharts
backend/    FastAPI + SQLAlchemy + PyMySQL + JWT
*.docx      原始 PRD 与开发验收清单
CURRENT_PRD.md          早期现状审计，保留历史背景
DEVELOPMENT_STATUS.md  最新任务状态与下一步
```

浏览器通过 Vite 将 `/api`、`/health` 代理到本地 FastAPI。后端连接远程 MySQL；数据库中已有 `denglu`、`operator`、`org_hierarchy`、`dp_ry`、`dny_data`、`daily_report`、`target_monthly`。`dny_data` 已建立 `(rq, dpbh)` 索引。数据库内容和连接凭据**不包含在仓库中**。

权限范围以登录角色和 `org_hierarchy` 为基础：普通运营仅本人，组长为本组，主管为名下，管理端为全量。经营总览和人员销售在服务端过滤；前端菜单隐藏仅用于体验，不是权限边界。旧统计接口仍需后端权限限制，见下文风险。

## 本地启动

环境：Python 3.10+、Node.js、npm，以及有访问权限的 MySQL。仅在可信内网环境使用开发服务。

1. 复制 `backend/.env.example` 为 `backend/.env`，填入数据库连接信息和随机生成的强 `SECRET_KEY`。`.env` 已被 Git 忽略。
2. 在 `backend` 目录执行 `python -m pip install -r requirements.txt`，再执行 `python main.py`。健康检查地址：`http://127.0.0.1:8000/health`。
3. 在 `frontend` 目录执行 `npm ci`，再执行 `npm run dev`。页面地址：`http://localhost:5173/login`。
4. 前端构建：在 `frontend` 执行 `npm run build`。

开发服务器默认监听所有网卡。正式部署必须设置前端实际域名、限制 CORS、关闭不必要的公网入口，并使用安全的凭据管理与 HTTPS。

## 核心接口

- `POST /api/v1/auth/login`、`GET /api/v1/auth/me`：登录与当前身份。
- `GET /api/v1/sales/daily`：日期/店铺/角色范围筛选，返回 `items`、`total`、`summary`、`stores`，每页 10–100 条。
- `GET /api/v1/sales/personnel`：7 日人员销售、部门/组别/运营筛选，返回 `items`、`total`、`options`，每页 10–100 条。
- `GET/POST /api/v1/report/daily`、`GET /api/v1/report/daily/mine`：日报列表、提交和本人回填。
- `GET/POST /api/v1/report/target`、`GET /api/v1/report/people`：月目标读写及可见人员。

前端将当前页数据缓存于组件内，并静默预取后两页；日期、店铺或人员筛选变化时重新查询。预取不等于预先渲染全部 DOM，也不使无权限数据进入浏览器。

## 验证与性能

2026-09-18 对管理员账号的只读接口测试：经营总览由约 20.09 秒、15.39 MB 全量响应，降为约 0.44 秒、27 KB、20 条首屏；人员销售由约 2.24 秒、1008 条全量响应，降为约 0.45 秒、13 KB、20 条首屏。第一页和第二页、四角色读取范围均已检查；前端 `npm run build` 通过。该数据是本地到远程库的单次测试，不是生产环境 SLA。
